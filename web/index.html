Prompts missing? Check capture
  1. Keep the service running and open Codex in the connected repository.
  2. Enable the plugin and review/trust its hooks in Codex using /hooks.
  3. The Codex process must inherit the connection's token environment variable. Restart an already-running app after setting it.
  4. Run node src/cli.ts doctor --root "<repository>" from the plugin source directory. Check the last prompt invocation, capture and delivery timestamps.
  5. Run node src/cli.ts flush --root "<repository>" if events are queued.
  6. Use a dashboard credential for the same project. Agents see their own events; administrators and observers see project events. Clear filters and send a new prompt.

Connection does not import old conversations. A prompt that never reached the hook cannot be recovered by flushing.

Write tests for this repository

Add your framework, test location, fixtures, commands and expected behavior to the local project-testing/SKILL.md. Follow the repository's existing setup.

Example request to Codex:

Read .agents/skills/project-testing/SKILL.md. Implement tests for the login flow. Cover valid input, invalid input, permission failures and expired sessions. Reuse our framework and fixtures, run the relevant tests, and report commands, results and remaining gaps.

To plan first, say: "Inspect this feature and propose test cases. Do not implement yet." Connecting the plugin alone does not write or run a test suite.
